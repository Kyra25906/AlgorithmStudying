# 第一课 vector 的元素、长度与容量

## 本课的已知和所求

已知：你会 C 数组、循环和基本输入。现在输入一批成绩，数量在运行时才确定。

所求：保存全部成绩，统计总分，按原顺序保留不低于 60 的成绩；同时正确处理空数据，避免越界，不手动管理动态内存。

完成本课应能解释 size、capacity、reserve、resize；正确使用下标与尾部操作；理解引用和扩容风险。完整代码见 [状态演示](../examples/01-vector-model.cpp) 与 [成绩程序](../examples/01-scores.cpp)。本课聚焦 vector<int>，暂不讨论 vector<bool> 的特殊化。

## 1 从 C 数组出发

第一反应可能是声明 int a[1000]，再用 n 记录实际用了多少位置。这个方法需要自己保证输入没有超过空间；若改为动态分配，还要负责释放和扩容。

vector 管理这组对象及其存储。它仍支持类似数组的下标访问，但能在运行时增加元素。

```cpp
#include <vector>
std::vector<int> scores;
scores.push_back(80);
scores.push_back(95);
```

逐句解释：std:: 表示标准库命名空间；vector 是容器模板；<int> 指定元素类型；scores 是变量名。push_back 在末尾建立一个新元素。

现在有效数据为 [80, 95]，下标为 0 和 1。vector<int> 的元素连续存储，按下标访问无需从头逐个寻找。

## 2 元素、长度和容量

```text
一个可能状态：size=3，capacity=6
下标           0    1    2  |  3    4    5
有效元素      80   95   60  |  预留空间
可用 a[i]      是   是   是 |  否   否   否
```

图中的 6 只是示意，不是某个操作后保证得到的容量。

- 元素：已经存在于容器中的对象。
- size：元素数量，决定合法下标范围 [0, size)。
- capacity：无需重新分配存储时，能容纳的元素数量。

始终满足 size <= capacity。有存储空间不代表有可访问的 vector 元素。预留区域不能直接用下标写入。

## 3 初始化的含义

```cpp
std::vector<int> a;       // 空，size=0
std::vector<int> b(3);    // [0, 0, 0]
std::vector<int> c(3, 7); // [7, 7, 7]
std::vector<int> d{3, 7}; // [3, 7]
```

圆括号 (3, 7) 在这里指定数量和初值；花括号 {3, 7} 指定两个元素。这里新建 int 为 0，不代表所有自定义类型都被初始化为数字 0。

## 4 一条状态链理解 reserve 与 resize

| 操作 | 有效元素 | size | capacity 信息 |
|---|---|---:|---|
| 创建空 a | 空 | 0 | 不小于 size |
| a.reserve(5) | 空 | 0 | 至少 5 |
| a.push_back(80) | 80 | 1 | 保持不变 |
| a.push_back(95) | 80,95 | 2 | 保持不变 |
| a.resize(4) | 80,95,0,0 | 4 | 保持不变 |
| a.resize(2) | 80,95 | 2 | 保持不变 |
| a.pop_back() | 80 | 1 | 保持不变 |
| a.clear() | 空 | 0 | 保持不变 |

reserve 预留空间，不增加元素。参数大于当前 capacity 时才重新分配；传入更小的值不会缩容。

resize 改变元素数量。缩小则删除末尾元素；增大则添加元素，本例新增 int 为 0。用 resize(4, 7) 则以 7 补足新增部分。若增长超过容量，还会触发重新分配。

知道要读入 n 个整数时，有两种正确方式：

```cpp
// 方式一：先建立 n 个元素，再覆盖其值
std::vector<int> a(n);
for (int i = 0; i < n; ++i) std::cin >> a[i];

// 方式二：先预留，再逐个增加元素
std::vector<int> b;
b.reserve(n);
for (int i = 0; i < n; ++i) {
    int x;
    std::cin >> x;
    b.push_back(x);
}
```

这两个片段假设 n 非负且输入成功，需要 <iostream> 和 <vector>；完整程序包含检查。

错误混合方式：先 vector<int> a(n)，再 push_back n 次，会得到 2n 个元素，前 n 个仍是初始化的 0。

## 5 访问前先确认元素存在

| 操作 | 含义或返回值 | 条件 |
|---|---|---|
| a[i] | 第 i 个元素的引用 | i 必须是合法下标，不检查越界 |
| a.at(i) | 第 i 个元素的引用 | 越界抛出 std::out_of_range |
| a.front() | 第一个元素的引用 | 非空 |
| a.back() | 最后一个元素的引用 | 非空 |
| a.empty() | 是否为空 | 总可调用 |
| a.pop_back() | 删除末尾，无返回值 | 非空 |

在 C++17 中，越界使用 operator[] 是未定义行为，不能以“没有崩溃”证明合法。演示程序用 at 安全展示边界检测，不实际执行越界下标。

```cpp
if (!a.empty()) {
    int last = a.back();  // 先读
    a.pop_back();        // 再删
}
```

size 返回无符号类型，空容器的 size()-1 会回绕。不要借此得到空容器的最后下标。

## 6 遍历中的副本和引用

```cpp
for (int x : a) x += 1;       // 只改副本，a 不变
for (int& x : a) x += 1;      // 修改原元素
for (const int& x : a) {      // 只读引用
    std::cout << x << ' ';
}
```

引用先理解为原对象的别名。int& 中的 & 属于类型声明，不是执行取地址。int 复制很便宜，读取时用 int x 很自然；以后读取大对象常用 const auto&。

改变元素的值与改变容器结构不同。不要在范围 for 中随意对同一 vector 追加或删除：结构变化可能使循环正在使用的位置失效。安全遍历删除放在第二课。

## 7 扩容与旧引用

空间不足时，vector 需要取得更大的存储区并转移旧元素。发生重新分配后，旧的元素引用、指针和迭代器失效。

```cpp
std::vector<int> a{10, 20};
int& first = a[0];
a.reserve(a.capacity() + 1); // 本例成功时必然重新分配
// 此后不再读取 first，它已失效
std::cout << a[0];           // 重新从容器取得元素
```

保留下标也不是所有修改的通用解决方案：在前面插入或删除后，同一下标可能对应别的元素。

容量不保证固定翻倍。状态程序记录本机增长情况，但不对倍数做断言。shrink_to_fit 是可不被满足的缩容请求，不是保证释放空间的命令。

## 8 为什么是这些复杂度

| 操作 | 复杂度与原因 |
|---|---|
| 下标、at、size、capacity、empty | O(1)，无需扫描 |
| push_back | 均摊 O(1)，单次扩容可能为 O(n) |
| pop_back | O(1)，只删末尾 |
| 中间插入或删除 | O(n)，可能搬移后面的元素 |
| 遍历 | O(n)，每个元素一次 |
| reserve 触发重新分配 | O(n)，转移已有元素 |

以上将单个 int 操作视为常数时间；自定义对象还要考虑构造、移动和析构代价。均摊分析的是一串操作的总成本，不保证每次操作都一样快。

不要在每次 push_back 前调用 reserve(size()+1)：这可能造成频繁搬移，破坏原有增长策略。

## 9 完整成绩程序

约定输入 n 在 0～100000 之间，随后有 n 个 0～100 的成绩。输出总分、合格人数和按原顺序排列的合格成绩。输入非法时报告错误并返回非零退出码。

程序在 [01-scores.cpp](../examples/01-scores.cpp)。先保存输入，再从左向右扫描。处理前 i 项后：total 等于这 i 项的总和，passed 恰好保存其中合格的成绩且顺序不变。这就是循环不变量。

```text
输入
5
80 59 100 60 40

输出
total=339
passed=3
scores: 80 100 60
```

n=0 时，输出 total=0、passed=0 和 scores:。时间 O(n)，保存数据的空间 O(n)。

5. 独立读入 n 个整数，删除末尾连续的 0。测试空序列、全部为 0、末尾非 0、中间有 0。
6. reserve 后引用一定失效吗？尾插均摊 O(1) 是否意味着每次都是 O(1)？
