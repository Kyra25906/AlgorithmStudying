# 第十一章 栈、队列与优先队列

## 已知与所求：下一次处理谁

假设依次收到任务 A、B、C。撤销操作应先撤销 C；窗口排队应先处理 A；紧急任务系统应先处理优先级最高的任务。这三种规则分别对应 stack、queue、priority_queue。它们是容器适配器：通过限制接口表达访问规则，不提供普通的 begin/end 遍历接口。

本课沿用 C++17。先会使用 vector、deque 和比较器，再学习这些接口。完整示例使用标准头文件，方便跨编译器编译。

## stack：后进先出

头文件 `<stack>`，默认底层是 deque。`push(x)` 在顶端添加，`top()` 返回顶端元素的引用，`pop()` 删除顶端但返回 void。`empty()` 判断是否为空，`size()` 返回元素数量。默认底层下这些操作为 O(1)。调用 top/pop 前必须确保非空。

状态演示：空栈 → push('(') 得到 ['('] → push('[') 得到 ['(', '[']，右侧是栈顶。读到 ']' 时应匹配 '['，匹配后 pop，只剩 '('。这说明栈保存的是尚未完成匹配的左括号。

括号匹配步骤：遇左括号入栈；遇右括号先检查空栈，再检查栈顶类型；匹配才弹出。扫描结束必须为空。本课约定只允许六种括号，其他字符直接判失败；空字符串合法。时间 O(n)，额外空间 O(n)。

不要写 `auto x=s.pop()`；应先 `auto x=s.top(); s.pop();`。若用引用接收 top，弹出该元素后引用悬空，不能再使用。

## queue：先进先出

头文件 `<queue>`，默认底层 deque。push 从队尾加入，front 返回队首引用，back 返回队尾引用，pop 删除队首且无返回值。默认底层下均为 O(1)，front/back/pop 要求非空。

入队 10、20、30，首次 front 是 10，pop 后 front 为 20。BFS 利用这个顺序按距离逐层处理节点；入队时标记访问可以避免同一节点重复入队。本课先验证队列顺序，图搜索留给综合课。

## priority_queue：每次取最高优先级

同样在 `<queue>`。默认 `priority_queue<int>` 的 top 是最大值；最小堆写作 `priority_queue<int, vector<int>, greater<int>>`，还需 `<vector>`、`<functional>`。

push/pop 为 O(log n)，top 为 O(1)。默认 vector 底层的单次 push 还可能因扩容移动元素，通常采用摊还分析。它只保证顶端优先级最高，并不保证内部整体有序。想按顺序取出所有元素，需要反复 top/pop，时间 O(n log n)，会清空队列。

比较器 `cmp(a,b)==true` 表示 a 在该排序关系中排在 b 前面，优先队列把关系中靠后的元素放在顶端。因此默认 less 得到最大堆，greater 得到最小堆。可用两项手算验证方向：若 a 更应该被先处理，就应让 cmp(a,b) 为 false、cmp(b,a) 为 true。

本课任务：priority 越大越早处理；同优先级 id 越小越早处理。比较器先返回 `a.priority < b.priority`，相同则返回 `a.id > b.id`。不能写 <=，否则相同对象也会被判为严格小于自身，破坏严格弱序。完全等价任务的弹出顺序没有稳定性保证；需要稳定到达顺序时显式保存序号并作为次关键字。

## 修改与生命周期

priority_queue 的 top 返回 const 引用，不能就地改优先级。需要更新任务时，可重新构建，或采用带版本号的惰性删除；后者将在综合任务中展开。不要通过外部可变状态改变已经入堆元素的比较结果，否则原有堆顺序可能不再符合新的关系。

适配器不提供统一的引用失效规则，要看底层容器。priority_queue 的 push/pop 还会重排底层元素；最简单的使用方式是复制 top，再 pop，不跨修改保存引用。
